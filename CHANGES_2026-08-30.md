# What was added — Aug 30, 2026

Closed three gaps between what the Growth/Premium plans promise on
assistq.in and what the backend actually did on its own, without breaking
anything that already worked. `node --check` passes clean on every edited
file.

## 1. WhatsApp follow-ups now actually send themselves (Premium)

Previously `processRealEstateAutomation()` marked a due follow-up
`"queued"` and stopped — a human still had to open the dashboard and click
send. That's not what "WhatsApp Cloud API — automated + template
messaging" promises.

Now, if `WA_PHONE_NUMBER_ID`, `WA_ACCESS_TOKEN`, and the new
`WA_FOLLOWUP_TEMPLATE_NAME` are all set, the automation worker sends the
follow-up itself the moment it comes due, using the same Cloud API call the
manual "Send template" button already used (refactored into a shared
`sendWhatsAppTemplate()` function so there's only one place that talks to
Meta's API). Each follow-up is only ever attempted once
(`autoSendAttempted`) — a bad number or an unapproved template won't get
retried every 60 seconds. On failure it stays `"queued"` exactly as before,
so the one-tap click-to-chat fallback is never removed, only supplemented.

**Setup:** create an approved WhatsApp template with exactly one body
variable (Meta Business Manager → WhatsApp Manager → Message Templates),
wait for approval, then set `WA_FOLLOWUP_TEMPLATE_NAME` to its exact name.
Nothing else changes — if you don't set it, behavior is identical to
before (manual queue only).

## 2. Keyword rank trend history (Growth + Premium)

The homepage demo shows keywords with position + trend arrows (e.g. "Pos.
4 ▲3"), but `/api/keywords/sync` only ever overwrote `lastPosition` — there
was no previous value to diff against, so that trend didn't really exist
anywhere in the dashboard.

Every sync now appends a snapshot to a capped 12-entry `history` array per
keyword and computes `trend` (previous position minus current — positive
means the keyword moved up). The Keywords page in the dashboard renders it
as a ▲/▼ pill next to the position, plus a "N syncs tracked" note once
there's enough history to matter. No setup required — this activates the
next time Search Console is synced.

## 3. Two scheduler fixes (Growth + Premium)

- **Weekly reports** — the hourly scheduler previously required
  `process.env.SMTP_HOST` to even attempt a send, but `sendWeeklyReport()`
  already prefers a client's connected Gmail account first and only falls
  back to SMTP. Any client using the documented Gmail-connect flow (instead
  of SMTP) silently never got their automatic weekly email — "Send report
  now" worked because it calls the same function directly, the scheduler
  just never reached it. Fixed by letting `sendWeeklyReport()` decide and
  logging its own `{ok:false, reason}` instead of gating on SMTP presence.
- **SEO audits** — previously only ran when someone clicked "Run audit."
  Added a 6-hourly check that re-runs the audit for any Growth/Premium
  client whose last audit is more than 7 days old (or who's never had one),
  and logs it to the activity feed. Starter is skipped — it has no
  dashboard to show an audit in. This is what actually makes "SEO health...
  monitored every month" true instead of aspirational.

## Nothing removed

All three changes are additive and fail safe: WhatsApp automation falls
back to manual queueing exactly as before if unconfigured, keyword sync
still works with zero history, and both scheduler fixes only add attempts
that previously silently didn't happen — no existing behavior for a
correctly-configured client changes.
